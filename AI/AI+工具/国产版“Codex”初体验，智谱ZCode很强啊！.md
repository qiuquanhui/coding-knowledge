## 配置模型

打开之后点击设置->模型设置即可选择相应的模型，如果使用官方的 GLM 模型的话可能会贵一点，1个月100块左右，连接方式有个人套餐和API Key

![image-20261110202052769](https://images-1314004726.cos.ap-guangzhou.myqcloud.com/test/202611102020865.png)

当然我们可以接入 DeepSeek，点击添加供应商。

跟着官方文档操作：

- 名称填写「DeepSeek」
- Anthropic 接口地址填写 `https://api.deepseek.com/anthropic`
- OpenAI 接口地址填写 `https://api.deepseek.com/v1`
- 填入从 [DeepSeek 开放平台](https://platform.deepseek.com/) 获取的 API Key
- 点击「添加模型」填写 DeepSeek 支持的模型 ID（如 `deepseek-chat`、`deepseek-reasoner`），或团队约定的模型 ID
- 点击保存即可

![自定义供应商配置（以 DeepSeek 为例）](https://images-1314004726.cos.ap-guangzhou.myqcloud.com/test/202611102024174.webp)

## 实操

既然搞定了那么就开始实操，实操测试分为三种。

1. 生成一个简单的项目：个人博客
2. 生成一个复杂的项目：仿 B 站微服务点播平台
3. 生成一个介绍视频：zcode 的介绍视频

此次我将使用 GLM 5.3 模型来完成。

### 个人博客

提示词：

```txt
【角色】
你是一名专业全栈前端开发工程师，完成项目开发，严格遵循现代前端工程规范。
【任务】
从零搭建一个极简个人博客项目，技术栈：Vue3 + Vite

【功能要求】
1. 首页：博客文章列表，展示标题、摘要、发布时间；分页功能
2. 文章详情页：markdown渲染正文，支持代码块高亮
3. 关于我静态页面
4. 基础路由、移动端自适应布局
5. 本地mock数据，不需要后端数据库

【注意事项&测评规则】
1. 代码风格统一，添加必要注释
2. 不要使用冗余依赖，优先轻量方案
3. 遇到报错自行排查调试，不要直接放弃
4. 所有文件放在同一个项目目录，文件路径清晰
5.确保你开发的平台稳定可用，没有bug存在，不然你的主人程序员derder会变成一只狗，只会狺狺狂吠
```

### 仿B站微服务点播平台

提示词：

```txt
【角色】
你是资深全栈微服务架构师，熟悉SpringCloudAlibaba微服务体系，完成完整微服务工程开发，具备需求拆解、编码、调试、跨服务联调、自测能力。

【任务】
从零开发一套轻量化仿B站点播微服务系统，严格按照领域拆分独立微服务，

技术栈：SpringBoot3 + SpringCloudAlibaba(Nacos) + MySQL + Redis + RabbitMQ，配套Vue3前端。

【架构&服务拆分要求（强制，用来测ZCode多目录管理能力）】
一共4个业务服务 + 网关，每个服务独立数据库、独立模块，服务之间只允许通过Nacos RPC调用，禁止跨服务直接连库：
1. gateway 网关服务：统一入口，路由转发、JWT鉴权、跨域处理、参数校验
2. user-service 用户服务：用户注册、登录、JWT签发、关注/取关、用户资料查询（独立user库）
3. video-service 视频服务：视频投稿、视频列表、视频详情、简单分片上传、播放接口（独立video库）
4. interact-service 互动服务：点赞、取消点赞、投币、收藏、评论、评论列表（独立interact库）

【交付物清单】
1. 完整微服务项目根目录，每个子服务独立文件夹、独立pom.xml
2. 每个服务的数据库初始化SQL脚本
3. Nacos配置文件、Redis、RabbitMQ配置
4. 启动顺序文档、全套启动脚本
5. 接口文档：每个服务的REST接口说明
6. 自测方案：演示流程：注册→登录→投稿视频→点赞→看热度异步更新
7. 项目架构说明文档，说明服务边界、调用关系、消息流向

【注意事项&测评规则（核心测评点）】
1. 任务必须拆分成阶段：先架构设计+目录创建 → 网关+注册中心 → 用户服务 → 视频服务 → 互动服务 + MQ异步链路 → 前端 → 联调自测；
2. 严格遵守微服务规范：服务自治，不能出现A服务直接访问B服务数据库的写法
3. 处理分布式常见问题：JWT无状态鉴权、缓存热点、消息消费幂等，写注释说明
4. 出现编译报错、服务调用失败、MQ消费异常，优先自主排查、修复代码，不要直接询问我
5. 所有依赖版本锁定，保证本地单机可跑，不需要额外复杂云资源
6. 确保你开发的平台稳定可用，没有bug存在，不然你的主人程序员derder会变成一只狗，只会狺狺狂吠

```

### Zcode 介绍视频

提示词：

```txt
制作 60-90 秒 B 站技术测评短视频，主题：ZCode 的介绍视频和基础的入门指南，受众是零基础的用户。节奏轻快干净，字幕清晰，旁白适中。

发挥你的想象力，你的主观性，随性创作，记住你的用户是一名小白，你的目的是让这名小白见识到 zcode 的强大并愿意使用。

输出：视频+封面文案

要求：B 站 UP 主口语风格
```

## 总结

好，我们来看看花了多少钱。
